# NOVA — منصة تعليمية عربية متقدمة

NOVA منصة تعليمية عربية مبنية بـ PHP وMySQL، تجمع بين اكتشاف الدورات، التسجيل، الملف الشخصي، لوحة المستخدم، ولوحة إدارة كاملة للمحتوى والمستخدمين والتسجيلات والرسائل. صُممت البنية لتكون قابلة للتوسع من موقع معهد تدريبي إلى منصة تعليمية متعددة المسارات.

**إعداد وتطوير:** المهندس طاهر القاضي

**الغرض الأكاديمي:** مشروع منصة تعليمية عربية يطبق إدارة المستخدمين والصلاحيات وقواعد البيانات ورفع الوسائط والتصميم المتجاوب.

## الرؤية والهدف

يهدف المشروع إلى توفير تجربة تعليمية عربية واضحة وسريعة وآمنة، مع واجهة متجاوبة وهوية بصرية حديثة تعتمد على تدرج بنفسجي/بنفسجي فاتح/وردي، ونظام صلاحيات يفصل بين الزائر والمستخدم والمدير.

## الوحدات الحالية

| الوحدة | الوظائف |
|---|---|
| الزائر | الصفحة الرئيسية، تصفح الدورات، البحث والتصفية، تفاصيل الدورة، التواصل، التسجيل والدخول |
| المستخدم | جلسة دخول آمنة، لوحة حساب، دوراتي، التسجيل في الدورات، الملف الشخصي، تغيير كلمة المرور والصورة |
| المدير | إحصاءات، CRUD للدورات والتصنيفات والمدربين، تفعيل المستخدمين، تغيير الصلاحيات، إدارة التسجيلات والرسائل |
| الوسائط | صور الدورات، صور الملفات الشخصية، روابط الفيديو التعريفية، مجلدات رفع محمية ومحددة الأنواع والحجم |
| البيانات | users, categories, instructors, courses, enrollments, messages |

## الخطة والمخطط العام

```text
الزائر
  ├── الرئيسية والهوية البصرية
  ├── البحث والتصنيف
  ├── تفاصيل الدورة والوسائط
  └── التسجيل / الدخول

المستخدم ← جلسة آمنة ← قاعدة البيانات
  ├── لوحة المستخدم
  ├── الملف الشخصي والصورة
  ├── دوراتي وحالة التسجيل
  └── التسجيل في دورة

المدير ← requireAdmin ← قاعدة البيانات
  ├── إدارة المستخدمين والتفعيل والأدوار
  ├── إدارة الدورات والصور والفيديو
  ├── إدارة التصنيفات والمدربين
  ├── إدارة التسجيلات
  └── إدارة الرسائل
```

### خطة التنفيذ المرحلية

1. **التحليل والتصميم:** تحديد أدوار الزائر والمستخدم والمدير، وتصميم تجربة RTL وهوية NOVA البصرية.
2. **الأساس البرمجي:** إعداد PHP وPDO والجلسات والاتصال الآمن بقاعدة MySQL.
3. **الحسابات والصلاحيات:** التسجيل، الدخول، الخروج، الملف الشخصي، التفعيل، وحماية لوحة الإدارة.
4. **إدارة المحتوى:** بناء عمليات الإضافة والتعديل والحذف للدورات والتصنيفات والمدربين والمستخدمين.
5. **الوسائط وتجربة المستخدم:** رفع الصور والفيديو، البحث والتصفية، البطاقات المتجاوبة، ولوحات المتابعة.
6. **الاختبار والنشر:** فحص المدخلات، الاستعلامات المجهزة، الجلسات، الروابط، HTTPS، والاستجابة على الشاشات المختلفة.

### مخطط قاعدة البيانات

```text
users (id PK, full_name, email UNIQUE, password, role, image, birth_date, is_active)
  │ 1
  └──────────────< enrollments >──────────────┐
                 (user_id FK, course_id FK)   │
                                               │ *
categories (id PK) 1 ───────────────< courses >
                                  (category_id FK, instructor_id FK)
instructors (id PK) 1 ────────────────< courses

messages (id PK, name, email, subject, message, is_read)
```

العلاقة بين `users` و`courses` هي علاقة متعدد إلى متعدد، وتمثلها `enrollments` مع قيد فريد يمنع تسجيل المستخدم في الدورة نفسها أكثر من مرة. أما `categories` و`instructors` فكل منهما يرتبط بعدة دورات.

## المكدس التقني

- PHP تقليدي منظم إلى صفحات ووحدات مشتركة.
- MySQL عبر PDO وprepared statements.
- HTML5 وCSS3 وواجهة RTL عربية متجاوبة.
- جلسات PHP بخصائص HttpOnly وSameSite وSecure عند HTTPS.
- `password_hash` و`password_verify` لكلمات المرور.
- رفع وسائط محدود إلى JPEG/PNG/WEBP وبحجم أقصى 2MB للصور.
- Git وGitHub للنشر والتتبع.

## الإعداد المحلي والإنتاج

1. أنشئ قاعدة MySQL جديدة.
2. استورد `database/schema.sql`.
3. اضبط `NOVA_DB_HOST`, `NOVA_DB_USER`, `NOVA_DB_PASS`, `NOVA_DB_NAME`, و`NOVA_SITE_URL` في بيئة التشغيل.
4. تأكد من قابلية الكتابة في `uploads/courses` و`uploads/users`.
5. أنشئ مستخدماً من التسجيل، ثم فعّله من لوحة الإدارة أو امنح أول مدير بشكل يدوي آمن.
6. لا ترفع كلمات المرور أو ملفات الإعداد المحلية أو التوكنات إلى GitHub.

## قواعد الأمان

يجب أن تبقى رسائل أخطاء قاعدة البيانات مخفية في الإنتاج، وأن تستخدم جميع الاستعلامات prepared statements، وأن تُنظف المخرجات بـ`htmlspecialchars`، وأن تقتصر عمليات الإدارة على المستخدم ذي الدور `admin`. قبل الإطلاق التجاري يُنصح بإضافة CSRF tokens لكل عمليات POST، تحويل عمليات الحذف والتفعيل من GET إلى POST، وتفعيل rate limiting للدخول، وفحص MIME الحقيقي للملفات المرفوعة، وتخزين الوسائط خارج جذر التنفيذ أو منع تنفيذ PHP داخل uploads.

## خارطة الطريق الاحترافية

- **المرحلة الأولى:** تثبيت الهوية البصرية، الحسابات، الصلاحيات، CRUD، البحث، رفع الصور، والفيديو التعريفي.
- **المرحلة الثانية:** مكتبة وسائط للمدير، خلفية فيديو اختيارية للصفحة الرئيسية، معاينة قبل الرفع، ضغط الصور، وتسجيل نشاط الإدارة.
- **المرحلة الثالثة:** دروس داخل الدورة، ملفات PDF، اختبارات، تقدم المستخدم، شهادات، إشعارات بريدية، وتحليلات.
- **المرحلة الرابعة:** API موثق، تطبيق جوال، نظام اشتراكات ومدفوعات، CDN للوسائط، نسخ احتياطية، مراقبة، واختبارات آلية.
